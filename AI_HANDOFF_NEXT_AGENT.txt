현재 프로젝트의 본질:
- 이 프로젝트는 CVP를 대체하는 제어 시스템이 아니다.
- 이 프로젝트는 CVP API / telemetry / snapshot 데이터를 활용하여, 사용자가 CVP 등록 장비의 현황과 사용 여부를 읽기 전용으로 조회하는 운영 포털이다.
- 1차 목적은 다음과 같다.
  - 현재 장비 현황을 조회
  - IP / BGP AS / VLAN / VRF / Config 사용 여부를 확인
  - 신규 장비 구축이나 신규 값 할당 전, 이미 사용 중인지 / 검토가 필요한지 / 사용 후보인지 판단을 돕기
- 중요한 점:
  - 운영 중인 중복 장애를 자동 감지하여 알람을 울리는 시스템이 1차 목적이 아니다.
  - "이 값을 새로 써도 되는가"를 판단하기 위한 조회 도구라는 철학이 중요하다.

현재 사용자와 합의된 방향:
- 조회 중심 UI
- CVP 연결 기반 snapshot 수집
- Config 파일 저장 + DB 메타데이터 저장
- portable 배포 가능 구조
- 칸반 보드 기능은 기존 조회 플랫폼 위에 별도 기능으로 확장 중

현재 구현 목표 진행 단계:
- 기존 조회 기능: 이미 1차 동작 구현됨
- 칸반 기능: 1차 단계만 진행됨
  - 완료: 칸반 보드 UI 틀 + 드래그 앤 드랍 + 카드 생성/수정/삭제/상세
  - 미완료: 기존 장비 선택 / 신규 장비 입력 / 체크리스트 / 진행률 / 예정 config / snapshot 표시 / diff / 자동 검증 / 이력 / CVP 자동 매칭

사용자가 명시한 칸반 구현 순서:
1. 칸반 보드 UI 틀 + 드래그 앤 드랍
2. 카드 생성/수정/상세
3. 기존 장비 선택 + 신규 장비 입력
4. 체크리스트 + 진행률
5. 예정 config + snapshot 표시
6. diff
7. 자동 검증
8. 이력
9. CVP 자동 매칭

현재 실제 구현은 위 순서 중 1, 2, 그리고 삭제까지 포함하여 끝난 상태이다.
3번 이후는 아직 시작하지 않았다.

kanban_cards 스키마:

- sort_order

- updated_at

의도:
- snapshot 테이블에 칸반 데이터를 섞지 않음
- 이후 확장 시 checklist, history, planned_config 등을 별도 테이블로 붙이기 쉬움

중요한 최근 수정 사항:
- reorder_cards()가 처음에는 payload가 전체 카드와 정확히 일치해야만 통과하게 되어 있었음
- 그 결과 드래그 후 `{"detail":"Reorder payload does not match stored cards."}` 오류가 발생함
- 이를 수정하여:
  - duplicate id 방지
  - unknown id 방지
  - 영향받은 컬럼만 sort_order normalize
  - delete 후에도 컬럼 정렬 normalize
  로 변경됨

즉, 현재 reorder 관련 백엔드 버그는 한 번 수정된 상태이다.

8. 최근 중요한 UX / CSS 이슈와 해결 이력
======================================================================

이 섹션은 매우 중요하다. 다음 AI가 같은 실수를 반복하지 않기 위함이다.

----------------------------------------------------------------------
8-1. 컬럼 상단 얇은 타이틀 레이아웃 고정 문제
----------------------------------------------------------------------

사용자 요구:
- 보류 / 작업 예정 / 준비 완료 등 컬럼 상단의 얇은 타이틀 레이아웃은 크기가 늘어나거나 줄어들면 안 됨
- 카드 수와 무관하게 항상 최상단에 고정되어 있어야 함
- 카드 영역만 아래로 자연스럽게 늘어나야 함

실수했던 점:
- 별도 상단 바를 만드는 식으로 잘못 해석하면 사용자가 강하게 거부함
- 사용자는 기존 컬럼 내부의 얇은 타이틀 레이아웃 그 자체가 고정되길 원했음

교훈:
- 사용자가 "구조를 바꾸지 말고 지금 있는 레이아웃을 그대로 고정"하길 원할 때는, 구조 자체를 새로 만들면 안 됨

----------------------------------------------------------------------
8-2. drag-and-drop reorder API 오류
----------------------------------------------------------------------

오류 메시지:
- {"detail":"Reorder payload does not match stored cards."}

원인:
- backend reorder 로직이 너무 엄격했음
- payload에 전체 카드 정확한 일치가 없으면 실패하게 되어 있었음

수정:
- unknown id / duplicate id만 막고
- 영향 컬럼만 normalize하는 방식으로 완화

결과:
- create / reorder / delete 흐름 검증 완료

----------------------------------------------------------------------
8-3. detail view에서 상단 공백 발생
----------------------------------------------------------------------

증상:
- 보드로 돌아가기 버튼 아래에 큰 빈 공간이 생겼음

원인:
- detail shell / layout의 min-height 및 align-content 처리 부정확

수정 방향:
- 상단 컨테이너는 시작점에 붙이고
- 아래 detail layout이 공간을 받도록 재조정

----------------------------------------------------------------------
8-4. 작업 설명 textarea 스크롤 방식 문제
----------------------------------------------------------------------

사용자 요구:
- 작업 설명이 길어지면 내부 스크롤 대신 박스가 아래로 커져야 함

해결:
- AutoGrowTextarea 도입
- textarea height를 scrollHeight 기준으로 자동 증가

----------------------------------------------------------------------
8-5. Task Summary 하단 빈 공간 문제
----------------------------------------------------------------------

최근 가장 중요한 CSS 문제.

증상:
- 좌측 Task Summary와 작업 단계 패널 하단에 불필요한 큰 빈 공간이 남았음

정확한 원인:
- kanban.css에서 다음 세 셀렉터에 공통 min-height가 걸려 있었음
  - .kanban-detail-summary-card
  - .kanban-step-panel
  - .kanban-detail-main
- 즉, 원래 오른쪽 Card Detail 높이 확보를 위해 준 값이 왼쪽 카드들까지 강제로 늘리고 있었음

수정:
- 공통 min-height 제거
- 오른쪽 .kanban-detail-main에만 별도 min-height 유지
- .kanban-step-panel은 align-self: start로 조정
- .kanban-detail-sidebar는 align-content: start로 변경

이 문제는 최근 수정되었고,
- lint 통과
- build 통과
상태이다.

다음 AI 주의사항:
- detail 레이아웃 높이 문제를 건드릴 때는 반드시 kanban.css에서 공통 규칙과 개별 규칙이 겹치지 않는지 먼저 확인할 것
- 특히 .kanban-detail-main 관련 규칙이 여러 군데 중복 정의되는지 항상 확인할 것

======================================================================

이 프로젝트는 "CVP 기반 읽기 전용 운영 포털"이 핵심이며, 칸반은 그 위에 얹는 별도 작업 관리 기능으로 확장 중이다.

중요한 것은 "추측하지 말고, 정확한 원인을 찾고, 검증 후 수정"하는 협업 방식이다.
